# Краткая памятка по уроку

Дата: 2026-07-09

Сегодня я познакомилась с тем, как в проекте можно использовать не только обычный код, но и инструменты вокруг AI-агента: хуки, команды, сабагентов, другого независимого агента для ревью, а также собственный плагин и локальный маркетплейс для него.

## Что было сделано

1. Изучены и настроены хуки Claude.
   - В `.claude/settings.json` добавлен `Stop` hook.
   - Такой хук запускается после остановки ответа Claude.
   - Сейчас он вызывает команду:

   ```bash
   codex exec "Review changes since last commit and write results to a file named planning/REVIEW.md"
   ```

   Смысл: автоматически запускать другого агента Codex, чтобы он независимо проверял изменения и писал результат в `planning/REVIEW.md`.

2. Изучена работа с другим агентом.
   - В `.claude/agents/` добавлены описания агентов:
     - `reviewer.md`
     - `codex-reviewer.md`
     - `change-reviewer`
   - Эти файлы объясняют Claude, какого агента можно вызвать и какую задачу он должен выполнить.
   - Главная идея: Claude не делает ревью сам, а запускает отдельного агента Codex через `codex exec`.

3. Создана пользовательская команда.
   - В `.claude/commands/doc-review.md` добавлена команда для ревью документации из папки `planning`.
   - Команда принимает аргумент с именем файла и просит добавить вопросы, уточнения, замечания и идеи для упрощения.

4. Изучены скрипты и команды автоматизации.
   - В этом уроке под "скриптами" использовались команды, которые агент может запускать автоматически.
   - Пример: команда внутри hook запускает независимое ревью.
   - Отдельно в документации проекта описаны будущие Docker-скрипты запуска и остановки приложения:
     - `scripts/start-linux.sh`
     - `scripts/stop-linux.sh`
     - `scripts/start-windows.ps1`
     - `scripts/stop-windows.ps1`
   - Важно: эти файлы сейчас описаны как целевая структура, но сама папка `scripts/` в проекте пока не создана.

5. Создан собственный плагин.
   - В папке `independent-reviewer/` создан плагин `independent-reviewer`.
   - Его манифест находится здесь:

   ```text
   independent-reviewer/.claude-plugin/plugin.lson
   ```

   - Плагин описывает свою задачу: выполнять независимое ревью всех изменений с последнего коммита.
   - Внутри плагина также есть hook:

   ```text
   independent-reviewer/hooks/hooks.json
   ```

   - Этот hook повторяет идею автоматического запуска Codex для ревью.

6. Создан локальный маркетплейс для плагина.
   - В корне добавлена папка `.claude-plugin/`.
   - В ней создан файл:

   ```text
   .claude-plugin/marketplace.json
   ```

   - Он описывает локальный marketplace `kamilla-tools`.
   - В marketplace зарегистрирован плагин `independent-reviewer`.
   - После этого плагин подключен в `.claude/settings.json`:

   ```json
   "independent-reviewer@kamilla-tools": true
   ```

7. Обновлена документация проекта.
   - В `README.md` уточнено, что `OPENROUTER_API_KEY` больше не является обязательным.
   - Добавлено объяснение, что для локального тестирования можно использовать `LLM_MOCK=true`.
   - В `planning/PLAN.md` сильно расширено техническое описание проекта:
     - архитектура приложения;
     - переменные окружения;
     - поведение mock LLM;
     - работа с OpenRouter;
     - работа с Massive API;
     - правила торговли;
     - структура базы данных;
     - API-контракты;
     - SSE-поток цен;
     - критерии готовности фич.

8. Получен результат независимого ревью.
   - Файл `planning/REVIEW.md` содержит вывод Codex по изменениям.
   - Основные замечания:
     - `Stop` hook сейчас запускает Codex после каждого ответа Claude, что может быть слишком часто и дорого по времени/токенам.
     - В `planning/PLAN.md` схема LLM смешивает намерения модели и результат выполнения backend.
     - `README_1.md` дублирует README и ссылается на scripts, которых пока нет.

## Как это создавалось по шагам

1. Сначала были добавлены локальные настройки Claude в `.claude/settings.json`.
2. Затем был описан hook, который реагирует на событие `Stop`.
3. В hook была добавлена shell-команда с `codex exec`, чтобы запускать отдельного агента.
4. После этого были созданы файлы агентов в `.claude/agents/`.
5. Для удобного ручного запуска ревью документации была добавлена команда `.claude/commands/doc-review.md`.
6. Потом была создана папка плагина `independent-reviewer/`.
7. Внутри плагина был создан manifest `plugin.lson`.
8. В плагин был добавлен собственный hook в `hooks/hooks.json`.
9. Затем был создан локальный marketplace в `.claude-plugin/marketplace.json`.
10. Плагин был зарегистрирован в marketplace и включен в `.claude/settings.json`.
11. После запуска независимого ревью Codex записал результат в `planning/REVIEW.md`.
12. Параллельно обновлялась документация проекта, чтобы будущие агенты лучше понимали архитектуру и требования.

## Для чего это нужно

- Хуки нужны, чтобы автоматически запускать действия в ответ на события Claude.
- Команды нужны, чтобы быстро выполнять повторяемые задачи по шаблону.
- Сабагенты нужны, чтобы разделять роли: один агент пишет или планирует, другой проверяет.
- `codex exec` нужен, чтобы подключить другого независимого AI-агента к работе над проектом.
- Плагин нужен, чтобы упаковать повторяемую функциональность и переиспользовать ее как отдельный инструмент.
- Marketplace нужен, чтобы зарегистрировать собственный плагин и подключать его по имени.
- `planning/REVIEW.md` нужен как файл с независимой проверкой текущих изменений.
